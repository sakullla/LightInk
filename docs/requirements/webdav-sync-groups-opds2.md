# WebDAV 同步、书架分组与 OPDS 2.0

本文记录 LightInk 这组功能的用户可见行为、数据边界和迁移约束。它是实现说明，不是 WebDAV 服务端的配置替代品。

## 功能范围

### 书籍与受管内容

- `local` 书籍保留原路径；执行导入或确认迁移时，Rust 以流式方式计算 SHA-256，并把正文复制到应用数据目录的内容寻址目录。
- 受管书籍的稳定 ID 为 `managed:<sha256>`。同一正文只创建一个 blob；旧的本地 ID 会写入别名表，阅读进度、标注和分组引用沿用到新 ID。
- 迁移面板先给出 `ready`、`duplicate`、`missing`、`tooLarge`、`unreadable` 状态。只提交用户勾选的可迁移条目；单项失败不会回滚已经成功的其他条目，也不会删除原文件。
- `localPath` 只用于当前设备的运行时定位，不会进入远端设备快照。跨设备首次得到的书籍只有元数据、封面和 `blobHash`，打开或选择离线保留时才下载正文。
- 下载先写临时文件，校验大小和 SHA-256 后再原子提交。校验失败只留下错误状态，不覆盖已有正文。

### 分组

书籍与自定义组是多对多关系。自定义组可重命名、排序、拖动和嵌套，树深最多 8 层；前端和 Rust 端都会拒绝循环或超深移动。父组的书籍集合是所有后代成员的并集并去重。删除父组只删除该组及直接成员关系，子组提升到原父级，书籍正文和元数据不会删除。

智能组是只读规则视图。内置规则包含全部、在读、未读、文字书、漫画、受管、远程、格式等；作者和系列只有在至少两本书匹配时生成。元数据、来源或阅读进度改变后，视图会重新计算成员。

### OPDS 1.x 与 2.0

客户端保留 `browse`、`search` 命令和现有 Atom/XML 行为，同时按响应 `Content-Type` 或首个非空字符识别 OPDS 2.0 JSON。两代协议都归一化为出版物或导航条目，支持：

- `metadata`、作者、系列、主题、封面和 acquisition 链接；
- `navigation`、`groups`、搜索模板及上一页/下一页链接；
- 以最终响应 URL 解析相对链接，避免重定向后基准地址错误。

导航条目只进入子 Feed；出版物条目才显示打开、缓存和格式选择。Feed 响应有 8 MiB 上限，并限制条目数、嵌套深度、URI 方案和纯文本简介。HTTPS 到 HTTP 的降级、内嵌凭据和跨源凭据转发始终拒绝。

## 数据库迁移

当前书库 schema 为 v8。打开数据库时按以下顺序逐个事务迁移，已经是目标版本时不执行写入：

| 版本 | 内容 |
| --- | --- |
| v5 | `blobHash`、可用性、离线保留、主题字段、`managed_blobs` 和旧 ID 别名 |
| v6 | `library_groups`、`library_group_members` 及父级索引 |
| v7 | 设备同步记录、冲突日志、同步元数据 |
| v8 | 受管 Markdown、资源、正文版本和未命名草稿 |

每一步都在 SQLite 事务中创建表/列并更新版本号；失败时该步整体回滚。数据库版本高于当前程序会进入错误状态，不会降级或覆盖文件。损坏索引会保留带时间戳的诊断副本后重建空索引，原始正文不受影响。

## WebDAV 协议与安全边界

### 配置

在「文件 → WebDAV 同步…」配置一个活动目标。支持 HTTPS Basic/Bearer；HTTP 或局域网地址必须明确勾选。Basic 密码可使用 Nextcloud 等服务的应用密码。禁止 Digest、OAuth、Cookie 和客户端证书。

地址、名称、鉴权类型和“需要凭据”标记写入本地配置。密码或 Bearer token 优先写入系统钥匙串，钥匙串不可用时仅保留在当前进程内。新设备不会从远端恢复凭据，必须重新输入。

### 远端布局

同步目标使用固定目录：

```text
LightInk/v1/profile.json
LightInk/v1/devices/<device-id>.json
LightInk/v1/blobs/sha256/<前两位>/<sha256>
```

设备只原子替换自己的完整快照（临时文件后 `MOVE`）。正文和资源按 SHA-256 内容寻址并使用条件 PUT；下载后检查响应大小和摘要。快照或正文损坏会让本次同步进入错误状态，不覆盖本地数据。

### 合并与删除

同步记录使用设备版本、因果上下文和修改时间。不同字段直接合并；同一字段并发修改按版本点、修改时间、设备 ID 和记录 ID 的固定顺序选出胜者，并将败者写入冲突日志。进度作为一个原子位置记录，标注和成员关系分别记录。

Markdown 正文冲突保留两个 blob，落败版本进入文档版本历史。组父边形成循环时删除版本较旧的边。删除记录使用 tombstone，避免离线设备再次上传旧值。远端没有引用的 blob 只有在合并状态持续达到保留期后才可清理。

同步在启动完成、网络恢复、本地白名单状态变化后 5 秒防抖，以及用户点击「立即同步」时触发；同一时间只有一个任务。失败会保留错误状态，用户可以取消或手动重试。

## 同步白名单

会同步：

- 受管书籍的元数据、封面、分组、离线保留标记和必要的正文 blob；
- 受管 Markdown、实际引用的安全相对 `assets/` 资源、版本历史和未命名草稿；
- 阅读进度、标注、受管最近项；
- 语言、主题 CSS、阅读布局、排版、漫画偏好、自动保存、缩放、侧栏、状态栏和不含凭据的 OPDS 源配置。

不会同步：

- WebDAV/OPDS 密码、Bearer token、钥匙串引用的秘密值；
- 外部书籍或未托管 Markdown 的绝对路径；
- 远程缓存、运行中的标签、临时文件和设备级崩溃快照；
- 打开且有未保存修改的文档正文。

偏好合并后通过现有服务订阅立即应用。后台发现打开文档有远端新版本时保留当前内容，并生成可恢复的冲突版本。

## 使用与恢复

1. 先在同步面板测试连接并保存目标，再执行一次手动同步。
2. 首次启用同步时预览旧书迁移，确认可迁移项；缺失或超限文件可稍后处理。
3. 书籍详情或自定义组菜单可切换“保留离线”；下一次同步完成下载，直接打开也会按需下载。
4. 发生冲突时打开同步面板，逐条确认并标记已处理；正文可从文档版本历史恢复，组循环会显示为已修正的父级关系。

## 验收建议与已知限制

建议至少用两个独立设备和一个本地 WebDAV 模拟服务验证：Basic/Bearer、重定向、PROPFIND/MKCOL/PUT/GET/MOVE、断线取消、条件写入、哈希错误、并发正文冲突、分组移动和离线保留。检查远端 JSON 与日志不得出现密码、令牌或本机绝对路径。

当前只支持一个活动同步目标，远端内容没有客户端加密；新设备必须重新输入凭据。服务端特有的 OPDS 扩展可能被忽略，未托管文件不会因为配置同步而自动纳入同步空间。Linux 本地运行 Cargo 测试需要安装 Tauri 的 WebKitGTK、JavaScriptCoreGTK 和 libsoup 系统开发包。
